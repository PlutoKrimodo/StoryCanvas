## 0. 一分钟结论（可直接作为汇报开场）

StoryCanvas 面向「不会画画的成年人」：输入一段故事文字，系统解析出角色/场景/物品/动作，
优化成绘图 Prompt，调用图像模型出插画，再绑定到绘本并导出多页 PDF。本轮范围收敛为
**用户管理**与**智能图像生成**两个子系统，**在线编辑器整体放弃**；在此之上追加了
**Guest-first（未登录先体验）**与**成本封顶**两项需求。当前状态：Phase 0–6 与 T-1 已完成，
前端视觉现代化（docs/17）已收尾，**Phase 10 测试完善、Phase 11 部署、Phase 12 报告未开始**。

一句话概括需求确认的结果：**功能面已经收敛且基本兑现，剩下的不确定性全部集中在
「成本与部署边界」和「测试与验收口径」两件事上**，这也是需要同学一起定的部分（见 §7）。

## 1. 角色与权限（对 SRS §9.1 的更正）

| 角色 | 能做什么 | 确认口径 |
|------|---------|---------|
| **游客**（未登录） | 访问 `/` 与 `/generate`、生成插画、预览、下载单图 | 免费额度 **1 张**（`GUEST_GENERATION_QUOTA`），用尽返回 429 并引导登录；首页游客入口只给「登录后保存到绘本」，**但保存动作目前只是产品口径，后端未强制**（见 Q3） |
| **注册用户** | 全部个人功能：绘本增删改查、生成、历史、保存到绘本、导出 PDF | 受全站每日额度约束（§3 D-2） |
| **管理员** | 用户/内容管理 | **本轮不做**，报告里作为「第二阶段 + 内容审核」的未来规划表述 |

- 身份实现：游客是**影子用户**（`users.is_guest`，外键仍 NOT NULL），持 7 天有效期的游客 JWT；
  注册/登录携带 `guest_id` 即**认领**，把游客期间的任务/图片/绘本归属转移到真实账号
  （`backend/services/UserService.cpp` `claimGuestResources`，登录后撤销该用户全部 Token）。
- 游客 Token 走的是同一套 `JwtFilter`（`is_guest` 声明只用于配额判断），因此 `/books`、
  `/generation` 等写接口对游客**在鉴权层面是通的**：「游客不能保存进绘本」目前是**首页入口的
  产品约束**，不是后端约束。需要拍板是否补后端校验，见 §7 Q3。
- **需同步更正**：`docs/01` §9.1「未登录用户只能访问注册/登录页面」已被 T-1 需求取代，见 §3 D-1。
- 资源归属校验的口径（已实现且有脚本断言）：**资源存在但不是自己的 → 403；资源不存在 → 404**。
  这样既守住归属，又不泄露「这个 ID 到底存不存在」。

## 3. 本轮发生变更、旧文档尚未跟进的需求（**这次确认工作的主要产出**）

| # | 变更 | 旧文档现状 | 确认结论 |
|---|------|-----------|---------|
| D-1 | **游客可访问生成能力** | `docs/01` §9.1 仍写「未登录只能访问注册/登录页」 | 需求改为三级：游客（限额出图）/ 用户（全功能）/ 资源归属隔离（非本人 403、不存在 404，见 FR-4）。SRS 需出 v2.1 修订 |
| D-2 | **成本成为一等需求**（新出现的非功能维度） | `docs/01` §4、`docs/16` §3.2 完全没有成本条目 | 全站每日生成上限 `GLOBAL_DAILY_GENERATION_CAP=20`，对游客与登录用户**同时生效**，按 **Asia/Shanghai 自然日**重置，超限返回 429「今日全站生成额度已用完…请明天再来」。理由：游客身份可无限重取，个人额度封不住**共用系统 Key** 的花费 |
| D-3 | **PDF 导出从「放弃」回到范围内** | `docs/16` §3.4 放弃清单里曾整体砍掉 | 以「轻量多页（前端生成）」形式加回：只按页序自动合成，**不含任何排版编辑**，边界不变 |
| D-4 | **AI 双模式（真实厂商 + Mock 兜底）** | `docs/01` §5.2 只写「需要网络」 | 需求口径改为：`LLM_PROVIDER`/`IMAGE_PROVIDER` 可切 `mock`，Mock 生成**真实 PNG**，因此「解析→生成→落盘→预览→导出 PDF」整条链路**无外网也能演示**。答辩日断网是可控风险 |
| D-5 | **凭据与启动安全进入验收项** | `docs/01` §10 只讲密码与 HTTPS | 追加三条：① 密钥只走环境变量、禁止入库/入版本库（配 `.githooks` 提交前拦截，见 `docs/10` §8.4）；② AI 服务 **fail-closed**：`ENVIRONMENT=production` 或监听非回环地址时，`INTERNAL_API_KEY` 为占位值即拒绝启动；③ 后端 ↔ AI 服务内网调用带密钥 |
| D-6 | **视觉与可用性可验收化** | 旧文档无 | `docs/17` 简约油画风主题落地：暖白画布 + 陶土主色、共享布局单点来源、**零新依赖 / 零外部字体 / 无暗色**，并写入 `prefers-reduced-motion` 降级。答辩观感从「主观评价」变成可检查条目 |

> D-2 是当前**最需要与同学确认的一条**：它直接决定「演示日能不能现场出图」，也决定
> 部署到公网上去不会变成匿名出图代理。

## 4. 非功能需求确认（含未达标项，如实标注）

| 维度 | 要求 | 当前状态 |
|------|------|---------|
| 性能 | 非 AI 接口 < 500ms；AI 生成 < 60s；首屏 < 3s | 生成侧超时预算：LLM 30s / 图像 120s / 后端调用 180s；前端轮询 2s、5 分钟封顶。**未经压测** |
| 并发 | 100+ 并发（测试目标） | ⚠️ 后端为**内存队列 + 工作线程**，AI 服务 `MAX_CONCURRENT_TASKS=5`、`TASK_RETRY_COUNT=3`；此目标**只作为第二阶段**，报告不宣称达成 |
| 安全 | 密码 bcrypt（cost 12）；凭据不落库；JWT 鉴权；资源归属校验；参数化查询；输入校验；**接口限流** | 前五项已实现。⚠️ **接口限流未实现**：`docs/16` §7.4 设想的「匿名 100 次/分、认证 1000 次/分、AI 生成 10 次/分」在代码里没有对应 filter（backend 仅有 CORS + JWT 两个过滤器），当前只有「游客 1 张 + 全站 20 张/天」两道闸 |
| 加密存储 | 确需落库的敏感字段用 AES-256-GCM | 🟡 配置项 `ENCRYPTION_KEY` 存在但**为空 → AES 路径未启用**；当前没有需要加密落库的字段，故暂时无害（若做 BYOK 立刻变成硬前置，见 Q1） |
| 可用性 | AI 异步不阻塞、失败可重试、任务超时控制 | ✅ 已实现；轮询失败不弹全局 toast，进度用时间缓动而非假百分比 |
| 可扩展 | Provider 抽象、存储抽象 | ✅ LLM/图像 Provider 可换；存储为本地目录 `storage/users/{uid}/books/{bid}/`，对象存储留接口 |
| 可维护 | 分层、统一响应、统一日志 | ✅ C++ 后端 controller/service/repository 分层；spdlog；前端 api/stores/hooks/components 分层 |
| 可演示 | 离线可跑、一键启动 | ✅ `scripts/start_all.sh`；`LLM_PROVIDER=mock IMAGE_PROVIDER=mock` 兜底 |

## 5. 明确不做（答辩口径，防止被追问拖进范围）

- **在线编辑子系统全部**：画布、元素增删改、移动/缩放/旋转/裁剪、文字排版、撤销重做、图层。
  连带移除 Fabric.js 依赖、`page_elements` 表、`book_pages.canvas_data` 字段；

  内容安全依赖厂商侧审核 + Prompt 约束（这一点在报告里要主动说明，不要等人问）。

## 8. 三分钟讲稿要点（照读即可）

1. **一句话项目**：给不会画画的成年人做的 AI 儿童绘本工具——一段故事文字 → 插画 → 绘本 → 多页 PDF。
2. **本周做了什么**：与项目组同学把需求重新对齐一遍，产出这份确认记录；重点是**发现三类不一致**——
   (a) 需求文档还写着「未登录只能看登录页」，而我们已经按 Guest-first 上线了游客生成与登录认领；
   (b) 旧需求里完全没有「成本」这一维度，而接真实模型后它变成了硬约束，现在全站 20 张/天按北京时间重置；
   (c) SRS 写了「接口限流」，代码里其实只有额度闸门，没有频控。
3. **结论**：功能面收敛为两个子系统，15 条功能需求里 **13 条已实现**（11 条已有脚本/单测证据，
   2 条要等真实 Key 才能验收），2 条明确不做；在线编辑器整体放弃；
   剩余不确定性集中在**成本与部署边界**和**测试分工**两件事，对应 §7 的 8 个问题需要一起定。
4. **收尾**：演示可断网（Mock 出真实 PNG），链路「游客出图 → 注册认领 → 保存绘本 → 导出 PDF」端到端可跑。

右下「待同学确认的 8 个问题」，底部一行状态：Phase 0–6 ✅ / T-1 ✅ / docs/17 ✅ / Phase 10–12 ⬜。
