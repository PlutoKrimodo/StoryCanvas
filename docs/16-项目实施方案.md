## 2. 项目概述

### 2.1 建设目标

构建一个"输入故事文字 → AI 生成插画 → 在线预览与保存"的系统，作为课程设计项目，需同时满足以下验收要求：

1. 功能完整：覆盖两大子系统（用户管理 / 智能图像生成）的 MVP 全部功能点
2. 架构清晰：前后端分层、职责单一、接口规范
3. 可演示：端到端流程可在数分钟内完成
4. 可报告：具备完整的报告素材与图表

> 建设重心为**智能图像生成子系统**，用户管理子系统为其他能力的前置支撑。

### 2.2 目标用户

| 用户类型 | 使用诉求 |
|---------|---------|
| 家长 | 为孩子快速制作个性化绘本插画 |
| 幼儿教师 | 制作教学用图画故事素材 |
| 绘本创作者 | 快速产出配图草稿 |

### 2.3 使用场景

用户注册登录后，用一段自然语言描述故事，系统解析出角色、场景与动作，优化为绘图 Prompt，调用图像生成服务产出风格化插画，用户在结果页预览、重新生成并保存到绘本项目中。

### 2.4 系统边界

- **系统内**：
  - 用户管理子系统：用户体系、认证鉴权、用户信息与密码管理、绘本项目 CRUD。
  - 智能图像生成子系统：文本解析、Prompt 优化、图像生成、任务状态管理、结果预览、重新生成。
- **系统外（依赖）**：LLM 服务、图像生成服务（MVP 阶段以 Mock Provider 替代）。
- **明确不在系统内**：画布在线编辑、元素排版、多页排版编辑、PDF 合成导出。

## 4. 技术选型

### 4.1 选型总表

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| 前端框架 | React + TypeScript | 18.x / 5.x | 生态成熟、类型安全 |
| 构建 | Vite | 5.x | 启动与构建快 |
| UI | Ant Design + Tailwind CSS | 5.x / 3.x | 组件齐全，快速成型 |
| 状态管理 | Zustand | 4.x | 轻量、学习成本低 |
| 路由/请求 | React Router / Axios | 6.x / - | 标配 |
| 后端语言 | C++ | C++17 | 课程技术要求 |
| 后端框架 | Drogon | 1.x | 高性能、功能完整 |
| 构建工具 | CMake | 3.16+ | 标配 |
| 后端库 | nlohmann/json、jwt-cpp、spdlog、drogon-orm | - | JSON/JWT/日志/ORM |
| 密码哈希 | bcrypt（libbcrypt） | cost ≥ 12 | 加盐、可调成本、抗暴力破解 |
| 对称加密 | OpenSSL（AES-256-GCM） | - | 敏感字段加密存储（按需） |
| AI 服务 | Python + FastAPI | 3.10+ / 0.104+ | 异步、类型校验、自动文档 |
| AI 抽象 | Provider 模式（LLM / Image） | - | 可切换、可 Mock |
| 数据库 | PostgreSQL | 15 | JSONB 存解析结果、UUID 主键 |
| 缓存 | Redis | 7.x（可选） | MVP 可用内存队列替代 |
| 部署 | Docker + Docker Compose + Nginx | - | 一键交付 |

> **已移除**：Fabric.js（随在线编辑子系统一并放弃）。

### 4.2 关键技术决策

1. **后端框架选型**：在 Drogon / Crow / Oat++ 中选 Drogon（功能完整、性能强），接受其学习成本。
2. **状态管理选型**：在 Zustand / Redux / Jotai 中选 Zustand（轻量、简单）。
3. **AI 任务状态归属**：任务状态由 C++ 后端持有并落库，AI Service 保持无状态，前端只对接后端一个状态源。
4. **异步机制**：MVP 使用内存队列 + 工作线程，Redis 队列作为第二阶段升级项。
5. **生成结果归属**：`book_pages` 降级为**页容器**（仅记录页码、标题与所引用图片），不再承载可编辑画布数据。
6. **存储抽象**：定义统一存储接口，MVP 用本地文件系统实现，预留对象存储实现。
7. **AI Provider 抽象**：LLM 与 Image 各自定义基类，Mock 实现用于开发与测试，真实实现作为开关。
8. **加密存储**：密码一律 bcrypt 单向哈希；密钥类敏感信息不落库，经环境变量/密钥仓库注入（详见 6.6）。

## 5. 系统架构

### 5.1 架构总览

```
┌─────────────────────────────────────────────┐
│              前端 (React + TS)               │
│   用户界面 / 绘本管理 / AI 生成与结果预览      │
└─────────────────────────────────────────────┘
                     │ HTTP/REST + JWT
                     ▼
┌─────────────────────────────────────────────┐
│             C++ 后端 (Drogon)                │
│  用户 / 绘本 / 生成任务 / 文件访问 / 密钥校验  │
└─────────────────────────────────────────────┘
                     │ HTTP/REST（内网 + API Key）
                     ▼
┌─────────────────────────────────────────────┐
│          Python AI Service (FastAPI)         │
│  文本解析 / Prompt 优化 / 图像生成 / Provider │
└─────────────────────────────────────────────┘
                     │ HTTP/REST
                     ▼
┌─────────────────────────────────────────────┐
│        外部 AI 服务（LLM / 图像生成）         │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│  数据层：PostgreSQL / Redis / 本地文件存储    │
└─────────────────────────────────────────────┘
```

### 5.2 各层职责

| 层 | 职责 | 约束 |
|----|------|------|
| 前端 | 界面渲染、路由守卫、状态管理、生成进度轮询、结果预览 | 不承载业务规则；**无画布编辑** |
| C++ 后端 | 认证鉴权、业务逻辑、数据持久化、任务编排、文件管理 | 唯一对外 API 出口 |
| AI Service | 文本解析、Prompt 优化、图像生成、Provider 抽象 | 无状态，仅内网调用，需内部 API Key |
| 数据层 | 结构化数据、缓存、文件 | 文件按用户/绘本分层存储 |

### 5.3 后端分层

| 层 | 职责 |
|----|------|
| Controller | 路由、参数解析、调用 Service、构造响应 |
| Service | 业务逻辑、事务、编排外部服务 |
| Repository | 数据访问、SQL、数据映射 |
| Model / DTO | 数据实体与传输对象、序列化与校验 |
| Filter | JWT 校验、CORS、限流 |
| Utils | JWT、密码（bcrypt）、加密（AES）、文件、校验、配置 |

**分层红线**：Controller 不写业务逻辑；Repository 不写业务规则；避免循环依赖。

### 5.4 通信设计

| 链路 | 协议 | 认证 | 超时 |
|------|------|------|------|
| 前端 → C++ 后端 | HTTP/JSON，URL 版本 `/api/v1` | JWT Bearer | 30s |
| C++ 后端 → AI Service | HTTP/JSON（内网） | 内部 API Key | 60s（可配） |
| AI Service → 外部 AI | HTTP/JSON | 服务商 API Key | LLM 30s / 图像 120s |

### 5.5 部署形态

| 环境 | 形态 |
|------|------|
| 开发 | Vite Dev Server(5173) + Drogon(8080) + Uvicorn(8000) + PostgreSQL(5432) + Redis(6379) |
| 生产 | Docker Compose 编排 + Nginx 反向代理 + 数据卷持久化 |

- 唯一约束：用户名唯一、邮箱唯一、同一绘本内页码唯一

### 6.6 加密与敏感数据存储设计

> 本节为 v2.0 新增。凡涉及账号、凭据、密钥的位置，均须按本节的「存什么、怎么存、存在哪」三要素落地。

#### 6.6.1 密码

| 项 | 约定 |
|----|------|
| 算法 | **bcrypt**（加盐，cost ≥ 12），可选升级 Argon2id |
| 存储字段 | `users.password_hash`，长度 ≥ 60，**单向不可逆** |
| 禁止项 | 禁止明文、禁止可逆加密（AES/MD5/SHA1 直存）、禁止前端明文回传后再存 |
| 校验方式 | 登录时 `bcrypt.checkpw(输入, password_hash)`，比较失败不区分「用户不存在/密码错误」 |
| 传输 | 密码仅在前端 → 后端链路传输，生产环境强制 HTTPS |
| 前端 | 不在 localStorage / 日志中留存密码 |
| 修改密码 | 校验原密码 → 重新哈希 → 更新，并撤销该用户已签发 Token |
| 强度 | ≥ 8 位，含大小写字母与数字；策略见 `docs/10` |

> **实现说明（与代码一致）**：后端按编译期能力自动选择算法——检测到 `libbcrypt` 时使用 **bcrypt**；
> 未安装时回退为 **PBKDF2-HMAC-SHA256**（OpenSSL，迭代 12 万次）。两种算法的哈希串自描述
> （`$2b$...` / `pbkdf2_sha256$...`），验证时自动识别，因此安装 `libbcrypt` 后可平滑升级，历史数据无需迁移。

#### 6.6.2 凭据与密钥（不可入库）

| 项 | 存放位置 | 说明 |
|----|---------|------|
| JWT_SECRET | 环境变量 / 密钥仓库 | 禁止写死在代码与 `config.json` 提交入库 |
| DB_PASSWORD | 环境变量 / 密钥仓库 | 同上 |
| OPENAI_API_KEY / STABILITY_API_KEY 等服务商 Key | 环境变量 / 密钥仓库 | 仅 AI Service 侧持有，不下发前端 |
| INTERNAL_API_KEY（内网调用） | 环境变量 | 后端 ↔ AI Service 双向校验 |

#### 6.6.3 确需落库的敏感字段

| 场景 | 方案 |
|------|------|
| 第三方凭据需长期保存（如用户自填 API Key，本阶段一般不需要） | AES-256-GCM 加密后存储，密钥经环境变量注入，密文含 IV 与 Tag |
| Refresh Token 需支持撤销 | 仅存 `token_hash`（SHA-256），不存明文；表结构可选 `refresh_tokens` |
| 生成/上传文件中的隐私元数据 | 清理 EXIF，文件名使用 UUID 重写 |

#### 6.6.4 传输与运行期

- 生产环境全程 HTTPS/TLS 1.2+（Nginx 终止），禁用弱套件
- 日志脱敏：不打印密码、Token、API Key、Authorization 头；必要时掩码输出
- 数据库连接使用参数化查询（防注入，亦防凭据拼接泄露）
- 生产关闭调试模式，错误响应不返回堆栈

### 6.7 待修正的数据问题

| 序号 | 问题 | 建议 |
|------|------|------|
| 1 | `book_pages.canvas_data` / `page_elements` 为编辑器遗留 | 本轮不写入；后续可直接移除两处结构 |
| 2 | `generated_images.task_id` 非空，但若后续支持上传图则无任务来源 | 本轮无上传入口，暂不引入 `files` 表 |
| 3 | JSONB 字段结构缺少统一约定 | 明确 `parsed_data`、`parameters`、`style_info` 的结构 |
| 4 | `users.password_hash` 无长度/算法标记 | 建议增加 `password_algo` 字段以便算法升级（可选） |

## 7. 接口契约

### 7.1 通用规范

- Base URL：`/api/v1`
- 认证：`Authorization: Bearer <token>`
- 内容类型：`application/json`
- 统一响应：`{ code, message, data }`
- 错误响应：`{ code, message, errors? }`，且 `data` 必须补齐为 `null`

### 7.2 HTTP 状态码

| 状态码 | 说明 |
|--------|------|
| 200 / 201 / 204 | 成功 / 创建成功 / 删除成功 |
| 400 / 401 / 403 | 参数错误 / 未认证 / 无权限 |
| 404 / 409 / 422 | 不存在 / 冲突 / 校验失败 |
| 429 / 500 / 504 | 限流 / 服务错误 / 上游超时 |

### 7.3 模块与接口清单

| 模块 | 前缀 | 主要接口 | 所属子系统 |
|------|------|---------|-----------|
| 认证 | /auth | register、login、refresh、logout | 用户管理 |
| 用户 | /users | me（GET/PUT）、me/password（PUT）、me/books（GET） | 用户管理 |
| 绘本 | /books | 创建、列表、详情、更新、删除 | 用户管理 |
| 生成 | /generation | 创建任务、查询状态、重新生成、取消、历史（加分项） | 图像生成 |
| 图片 | /images | 详情、下载、列表 | 图像生成 |
| 健康 | /health | 数据库 / AI 服务状态 | 公共 |

**已移除接口**：`/pages/{id}` 画布更新、`/elements/*`、`/books/{id}/export`（PDF）。

### 7.4 安全要求

| 项 | 要求 |
|----|------|
| 认证 | 受保护接口必须携带 JWT |
| 授权 | 用户只能访问自己的资源，服务端自动校验归属 |
| 凭据 | 密码仅经 HTTPS 传输，服务端 bcrypt 校验，全程不落日志 |
| 限流 | 匿名 100 次/分、认证 1000 次/分、AI 生成 10 次/分 |
| 体积 | 普通请求 1MB |
| 校验 | 入参类型、长度、格式统一校验，返回 422 与字段级错误 |

### 7.5 待统一的接口问题

| 序号 | 问题 | 建议 |
|------|------|------|
| 1 | AI Service 对外接口与后端对外接口命名易混淆 | AI 侧拆为 `analysis/parse` 与 `images/generate` 两个明确端点 |
| 2 | 过滤器返回的错误响应缺少 `data` 字段 | 统一补齐 `data: null` |
| 3 | CORS 以 Controller 实现不符合语义 | 改为过滤器或全局中间件实现 |
| 4 | 密码相关错误信息可能泄露账号是否存在 | 登录失败统一返回「用户名或密码错误」 |

## 11. 质量保障

### 11.1 开发规范

| 维度 | 措施 |
|------|------|
| 分层 | Controller 无业务逻辑，Repository 无业务规则，Service 承载业务 |
| 前端 | 统一 API 层与状态层，组件职责单一 |
| 命名 | 统一命名规范，接口与数据库字段保持语义一致 |
| 契约 | 所有响应遵循统一响应结构 |

### 11.2 版本管理

- 分支模型：main / develop / feature / release / hotfix
- 提交规范：feat / fix / docs / style / refactor / test / chore / perf，并标注范围
- 关键改动走 Pull Request 评审

### 11.3 测试策略

| 类型 | 工具 | 范围 |
|------|------|------|
| 单元测试 | GoogleTest / pytest / Jest | 核心业务逻辑与工具类（含密码与加密工具） |
| 接口测试 | 自动化脚本 | 全部 REST 接口 |
| 数据库测试 | SQL 与断言 | 持久化、级联删除、索引 |
| 集成测试 | 端到端脚本 | 生成流程主链路 |
| 端到端测试 | Playwright | 用户主流程（注册→登录→生成→预览） |
| 安全测试 | 用例集 | 密码哈希、越权访问、限流、日志脱敏 |

**目标**：核心功能覆盖率 80%；接口响应时间 < 500ms；首屏 < 3s。

### 11.4 安全与加密基线

1. **密码存储**：bcrypt 加盐哈希（cost ≥ 12），禁止明文/可逆加密/弱哈希
2. **敏感配置**：JWT_SECRET、DB_PASSWORD、外部 API Key 一律经环境变量/密钥仓库注入，禁止硬编码与入库
3. **按需加密**：确需落库的敏感字段使用 AES-256-GCM，密钥独立注入
4. **传输加密**：生产全程 HTTPS/TLS 1.2+
5. **认证**：JWT 双 Token，支持刷新与撤销；修改密码后撤销历史 Token
6. **授权**：所有资源操作校验归属，实现用户隔离
7. **数据访问**：全部数据库操作使用参数化查询
8. **日志**：密码、Token、密钥、Authorization 头不落日志，必要时掩码
9. **接口防护**：限流与请求体积限制
10. **错误信息**：登录失败统一提示，不泄露账号是否存在

### 11.5 可观测性

- 后端使用 spdlog，AI 服务使用标准日志
- 记录 API 响应时间、错误率、并发数、生成成功率
- 任务处理记录耗时与队列状态
