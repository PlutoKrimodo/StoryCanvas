# 系统总体架构设计

## 基于生成式 AI 的儿童绘本智能创作与图像生成系统

**版本**: 2.0  
**日期**: 2026-09-19  
**作者**: StoryCanvas 开发团队

> **v2.0 修订**：范围收敛为**用户管理**与**智能图像生成**两大子系统，**在线编辑子系统整体放弃**，Fabric.js 与画布相关分层已移除。权威方案见 `docs/16-项目实施方案.md`。

### 1.2 架构原则

1. **分层架构**: 清晰的层次分离，便于维护和扩展
2. **职责分离**: 每个组件职责单一，避免耦合
3. **异步处理**: AI 任务异步执行，不阻塞用户操作
4. **可扩展性**: 支持未来功能扩展和技术升级
5. **课程项目友好**: 保持适度复杂度，确保可完成性

- 调用图像生成 API
- 返回生成结果

## 6. 通信设计

### 6.1 前端 ↔ C++ 后端

- **协议**: HTTP/HTTPS
- **格式**: JSON
- **认证**: JWT Token（Header: Authorization）
- **版本**: URL Path（/api/v1/...）

### 6.2 C++ 后端 ↔ Python AI Service

- **协议**: HTTP（内部网络）
- **格式**: JSON
- **认证**: 内部 API Key
- **超时**: 60 秒（可配置）

### 6.3 通信流程

```
用户操作 → 前端 → C++ 后端 → Python AI Service → 外部 AI API
                                    │
                                    └── 返回结果 → C++ 后端 → 前端 → 用户
```

## 7. 安全架构

### 7.1 认证机制

- **JWT Token**: Access Token + Refresh Token
- **Token 存储**: 前端 localStorage/HttpOnly Cookie
- **Token 刷新**: 自动刷新机制

### 7.2 权限控制

- **用户隔离**: 用户只能访问自己的资源
- **API 权限**: 公开 API vs 认证 API
- **资源验证**: 操作前验证资源所有权

### 7.3 数据安全

- **密码加密存储**: bcrypt 加盐哈希（cost ≥ 12），单向不可逆
- **凭据管理**: JWT Secret / DB 口令 / 外部 API Key 不落库，经环境变量注入
- **敏感字段加密**: 确需落库的敏感字段使用 AES-256-GCM
- **传输加密**: HTTPS/TLS 1.2+
- **输入验证**: 防止注入攻击
- **日志脱敏**: 密码、Token、密钥不落日志

## 8. 部署架构

### 8.1 开发环境

- **前端**: Vite Dev Server（端口 5173）
- **C++ 后端**: Drogon（端口 8080）
- **Python AI Service**: Uvicorn（端口 8000）
- **PostgreSQL**: 本地或 Docker（端口 5432）
- **Redis**: Docker（端口 6379）

### 8.2 生产环境

- **容器化**: Docker + Docker Compose
- **反向代理**: Nginx
- **数据库**: PostgreSQL 容器
- **缓存**: Redis 容器
- **文件存储**: 本地/MinIO

### 8.3 Docker Compose 布局

```yaml
version: '3.8'
services:
  frontend:
    build: ./frontend
    ports:
      - "80:80"
  
  backend:
    build: ./backend
    ports:
      - "8080:8080"
    depends_on:
      - postgres
      - redis
  
  ai-service:
    build: ./ai-service
    ports:
      - "8000:8000"

    image: postgres:15

      - "5432:5432"

  postgres_data:
```
